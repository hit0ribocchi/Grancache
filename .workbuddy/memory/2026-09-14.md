### ACGPower 本地缓存机制（关键结论）

1. 存储：`cache/gbf/<url 路径>` 路径镜像 + 同名 `.ext` JSON
   （字段 `LastModified/ETag/at/md5/ce/ct/v`）。
2. 魔改层：`<base>_ap.<ext>` 存在则**无条件优先返回**，走 `.ext` 取 ct/ce，
   否则按扩展名表猜（默认 `application/octet-stream`）。
3. 新鲜度：GBF 专属"信任窗口" —— `gbflocalcachecheck` 下 `gbfCacheControlTime`
   分钟内不校验；窗口外才发 HEAD 条件请求；另有 `localcachehit` 内存标记。
4. 写入条件：200 + Content-Length 与实际一致 + 静态扩展名；文件 mtime 设 Last-Modified。
5. 小优化：OPTIONS 预检本地 200 + `max-age=604360`；素材响应强制
   `Cache-Control: public, max-age=7200`；`/rest/error/js` 打桩；
   `/socket/uri/raid` 按 uid 做 60 秒内存缓存。

### 联网调研得到的新事实（都已写进计划）

1. **ACGPower 新版目录多一层 scheme**：社区实拍 ACGPower 3.1.1.8 PC 的路径是
   `cache\gbf\https\assets\img\sp\assets\npc\my\`（NGA 2024 魔改帖），
   而 2.5.1 安卓反编译里只是 `cache/gbf/<path>`。→ 最终布局定为
   `<cacheDir>/<scheme>/<host>/<url 路径>`，导入工具可整棵复制。
2. **ACGPower 缓存包不带 host 层** → 设计「主机回退」：本机 miss 时再查
   `config.cacheHostFallback`（默认主素材 CDN）目录。顺带让我们自己跨 CDN 去重。
3. **ACGPower 直接丢弃 query**（只用 `uri.AbsolutePath`）→ 我们保留 `__q_<encoded>` 一层，
   但加「版本 query 回退」：`__q_` 未命中时回查无 query 的同路径文件。
4. **魔改必须同时改浏览器缓存策略**（社区帖子反复要求 Ctrl+F5 才生效）：
   我们现在对版本化素材发 `immutable, max-age=31536000`，浏览器缓存过原图后
   放了 `_ap` 也永远不会来问代理 → 新增：OVERRIDE 响应改 `cache-control: no-cache`
   + `ETag: ap-<mtime>-<size>`，命中 ETag 时回 304。
5. 成熟方案对照：nginx `proxy_cache`（结构上与我们同级，但它是 hash 分级布局、
   目录不可读；值得抄的是 `inactive` 闲置淘汰与 `stale-if-error`，记为 M2）；
   `http-cache-semantics`（RFC 9111 正确实现，不引依赖但拿它当 policy.js 的对照清单）；
   `cacache`（`X-Local-Cache-Status` 语义值得抄进 `X-GBF-Cache`）；
   `frizz925/gbf-proxy`（同款 GBF 代理，issue 里自己都缺磁盘层缓存）。
6. 响应头语义细化：新增 `OVERRIDE` / `OPTIONS-HIT` / `REVALIDATED` / `MISS-NOSTORE`。
